# 01｜产品需求文档

## 1. 产品边界

面向量化策略实习生的中文、公开、可复现学习产品。它不是交易系统、投顾产品、实时行情服务或通用回测平台；不建设登录、数据库、消息队列、订单路由和实盘交易能力。

## 2. 需求来源

| 来源 | 含义 |
|---|---|
| OR | 原始需求，见未修改的 `REQUIREMENTS.md` |
| UC | 用户在设计轮次中确认的真实环境、数据权限与交付条件 |
| DD | 本轮为消除实施歧义而冻结的设计决策 |
| AS | 实施时必须验证的假设，不得伪装成事实 |

## 3. 原始目标

- OR-001：形成可用于实习生训练的完整学习体验。
- OR-002：覆盖数据、因子、组合、回测、评估与研究诚信。
- OR-003：以沪深 300 三因子案例贯穿。
- OR-004：兼顾 30 分钟、3 小时与深入学习。
- OR-005：结果可复现、可评审、可公开分享。
- OR-006：记录 AI 协作提示词与设计决策。

## 4. 用户目标

- GOAL-001：用户本人可按八步脚本完成实施前后自测。
- GOAL-002：用户能定位至少一个故意失败实验的错误来源。
- GOAL-003：用户能用模板提出新的、可验证研究问题。
- GOAL-004：自动化代理与用户本机可从干净环境复现同一产物。
- GOAL-005：从 GitHub 首页冷启动，无口头补充即可找到站点、运行入口、权限说明与三条路线。

外部实习生、第二台机器和三名代表性用户的测试是未来正式研究指标，不是本阶段硬门。

## 7. 验收标准

- AC-001：20 步、三条路径与导航无断链。
- AC-002：九端点探测报告含权限、实际代码、字段、行数、范围和适用性。
- AC-003：真实数据主流程在用户提供 Token 后可运行；无 Token 的行为明确且不会伪造正式结果。
- AC-004：公式、标签、时钟、基准与组合收益口径通过测试和人工复核。
- AC-005：正确案例及至少四个失败实验可重现，差异有解释。
- AC-006：D/T/P 任一红灯会阻止有效研究结论；S/C/R 失败给出补充研究或停止建议。
- AC-007：相同输入的复现运行不增加研究决策次数；参数改动后的确认结果标记污染。
- AC-008：统一命令完成 setup、test、build、preview；Notebook E2E、离线构建、链接和视觉检查通过。
- AC-009：README 冷启动与八步用户自测通过。
- AC-010：Pages URL 可访问；若外部服务阻断，仅按已定义规则交付离线 HTML 并记录阻断。
- AC-011：安全与许可审计无阻断项，仓库及历史不含秘密或禁止发布数据。

## 8. 已确认事实与实施假设

实施验证事实：项目使用 uv 0.12.7 管理的 CPython 3.12.14 与 Quarto 1.10.18；Token 已在仓库外权限 600 的文件中安全配置并通过非泄漏验证，本文不记录值、长度、前后缀或哈希。九端点最小探测均成功；实际全收益基准为 `H00300.CSI`（含股息），价格及成分代码为 `000300.SH`。

仍属明确限制：Tushare 返回记录不能证明历史 `index_weight` 的精确发布时间；全量 `stk_limit` 批量模式未形成正式成交所需覆盖。因此真实案例失败关闭为可信停止，不把诊断收益冒充可成交结果。Pages 外部可达性在部署阶段继续验证。

## 9. 不做事项

不接实盘、不提供投资建议、不承诺收益、不引入无关后端、不公开授权原始数据、不把确定性教学夹具当成真实研究证据。
