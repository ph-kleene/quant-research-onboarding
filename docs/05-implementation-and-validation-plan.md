## 4. 阶段门

### Gate A｜环境与秘密

- uv 管理的 Python 3.12、Quarto 和依赖版本已记录。
- Token 仅来自环境变量或权限 600 的仓库外文件。
- `.gitignore` 与初始秘密/历史扫描通过。

### Gate B｜真实数据能力

- 九端点全部完成最小探测。
- 请求总量已重新估算，限速、退避、续跑和缓存冲突测试通过。
- 总收益候选只在 `index_basic` 发现后探测；主基准记录实际代码。
- 每个失败端点只按矩阵启用唯一回退，否则停止该能力。

### Gate C｜研究正确性

- `usable_from <= signal_at < execution_at` 全量断言通过。
- 复权收益、标签、组合收益、实际成交成本与基准区间测试通过。
- 四个失败实验可重现；D/T/P 红灯能阻断研究有效性。
- 确认期首次揭示前已有冻结键和协议，计数与污染规则可审计。

### Gate D｜产品交付

- 20 步、三路线、README、Notebook E2E、离线 HTML、链接和视觉检查通过。
- 公开安全/许可审计通过。
- Pages 最终 URL 可访问；外部服务阻断时按已定义降级保留证据。
- 用户本人完成八步自测。

## 5. 用户验收脚本

用户从 GitHub 首页开始：找到 30 分钟路线和站点 → 按统一命令运行/查看案例 → 识别故意失败 → 解读 REG 双结论 → 用模板提出新问题 → 记录障碍与错误 → 判断是否适合实习生训练 → 保存最终 URL 与判断理由。

实施代理同时执行自动化测试、离线构建、Notebook E2E、正确/失败门、链接、视觉和 README 冷启动。三名代表性用户、第二台机器复现等外部验证留作后续指标，不阻断本阶段。

## 6. 故障与降级处理

- 端点权限/字段/覆盖失败：应用该端点唯一回退，记录 API 状态和研究影响；不得用教学夹具填充正式研究。
- 历史发布时间不可证明：标黄并执行更保守滞后一日/一月敏感性。
- Pages 阻断：保留配置和证据，交付同源离线 HTML，恢复后补测 URL。
- PDF 阻断：推迟 T104。
- 安全扫描命中密钥：停止推送和发布；轮换、清历史、清缓存并全量复扫。
- Tushare 许可不明确：公开夹具、方法、不可逆聚合；原始数据和可重构缓存留在仓库外。
