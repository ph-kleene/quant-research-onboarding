# 02｜方案比较与决策

## 1. 候选方案

### A｜Notebook 单体

用一个或少量 Notebook 同时承载教程、数据处理和回测。启动快，但导航、测试、复用、离线发布和研究治理都弱。

### B｜Quarto 站点 + Notebook + 模块化研究管线

Quarto 负责学习体验与发布，Notebook 展示可执行路径，模块承载数据/研究逻辑，测试和研究护照形成质量闭环。初始结构稍多，但最符合公开、可复现和可教学目标。

### C｜交互式 Web 应用

以 Dashboard/应用为主要界面。交互强，但会引入服务、状态和部署复杂度，削弱文档可审计性，且不适合本阶段。

## 2. 加权决策矩阵

评分 1—5，5 为最佳。

| 维度 | 权重 | A | B | C |
|---|---:|---:|---:|---:|
| 教学路径与叙事 | 20 | 3 | 5 | 4 |
| 研究严谨与可审计 | 20 | 2 | 5 | 3 |
| 可复现与自动测试 | 15 | 2 | 5 | 3 |
| 公开/离线交付 | 15 | 3 | 5 | 2 |
| 实施复杂度 | 10 | 5 | 4 | 1 |
| 内容与逻辑复用 | 10 | 2 | 5 | 3 |
| 安全与许可控制 | 10 | 3 | 5 | 2 |
| 加权总分 / 5 | 100 | 2.75 | **4.90** | 2.75 |

## 3. 最终决定

唯一推荐 B。采用以下边界：

- Quarto 是内容与发布层，GitHub Pages 是 P0 公共入口，离线 HTML 是等价备用入口。
- Notebook 是可执行教学入口，不是唯一逻辑源。
- Python 模块是数据契约、因子、组合、评价与验证的事实源。
- uv 安装并固定 CPython 3.12、锁定依赖；统一脚本包装环境、测试、构建和预览。
- 真实 Tushare 是正式案例主路线，九端点先探测后使用。
- 确定性教学夹具只服务测试、无 Token 预览和失败演示。
- PDF 是 P1 便利产物，不进入 P0 阻断链。

## 4. 决策理由

B 同时保留课程的线性叙事、Notebook 的可执行性和软件模块的可测试性。它允许 Pages、离线 HTML、Notebook 和测试共享同一套冻结事实源，也使 Token、缓存、原始数据与公开产物能够明确隔离。与单体 Notebook 相比，B 更容易证明没有时点泄漏；与 Web 应用相比，B 不引入本阶段不需要的运行服务。

## 5. 固定技术选择

| 项目 | 决策 |
|---|---|
| 文档与站点 | Quarto |
| 运行环境 | uv 管理的 CPython 3.12 |
| 研究接口 | Python 模块 + 可执行 Notebook |
| 正式数据 | Tushare，经能力探测与不可变缓存 |
| 教学数据 | 小型、确定性、可公开夹具 |
| 发布 | GitHub Pages + 离线 HTML |
| PDF | P1，按价值安装浏览器/TinyTeX |
| 自动化 | 单元/契约/泄漏/回归/E2E/构建/链接/安全检查 |
| 统一命令 | `bash scripts/project.sh setup|test|build|preview` |

## 6. 降级与回退

降级以能力为单位，不以时间不足为理由删掉核心：

1. 单个 Tushare 端点失败：使用技术设计矩阵中该端点的唯一回退，并在护照中标明影响；没有合规回退则停止相关研究能力。
2. 总收益指数不可用：使用 `index_basic` 实际发现并由 `index_daily` 探测成功的沪深 300 价格指数，明确写“价格指数”且弱化相对超额硬门。
3. 无 Token：只运行测试夹具与界面预览，正式案例显示“未执行”，不得显示伪真实结果。
4. Pages 外部阻断：交付同源离线 HTML、保留 Pages 配置和阻断记录，恢复后重试。
5. PDF 工具链失败：延后 P1 PDF，HTML、Notebook、研究与 Pages 不受影响。

## 7. 被否决的扩展

本阶段不采用数据库、登录、任务队列、实时行情、交易接口、复杂前端状态管理或通用策略插件系统。这些内容不改善当前验收目标，且会扩大安全与复现面。
